On the Mac, the window is the object people move, resize, and minimize. Your SwiftUI app is a `Scene` that creates those windows. The iPhone layout you practiced, a single column with a huge bottom button, looks lost in the middle of a 1400-point display.

Start from the macOS App template. Run it on your Mac. There is no phone simulator in this path.

## A window with a job

```swift
import SwiftUI

@main
struct DeskApp: App {
    var body: some Scene {
        WindowGroup {
            Text("Lessons on this Mac")
                .frame(minWidth: 420, minHeight: 280)
        }
        .defaultSize(width: 720, height: 480)
        .windowResizability(.contentMinSize)
    }
}
```

`WindowGroup` means the person can open more than one window from the File menu, unless you later restrict it. That is a feature. Treat each window as a view onto the work, not as the entire app process.

Set a navigation title once you have a stack or a split view. The title becomes the window title. "ContentView" is not a title.

<Callout title="Where people stall">

They port an iPhone `TabView` unchanged and call it a Mac app. The HIG for macOS expects a window that uses the width: sidebar, content, perhaps an inspector. Read Designing for macOS before you add a second control. Also, previews on macOS are useful, but run the app. Window sizing bugs hide in previews.

</Callout>

<Surfaces>

## Exercise

Create a macOS app whose window title is "Study Desk". Give it a minimum size that still shows a title and a button. Resize it smaller than the minimum and confirm the content does not clip into a useless sliver.

<Solution>

Put `.navigationTitle("Study Desk")` on the root inside a `NavigationStack`, or set the window style your SDK documents for titles. `defaultSize` and `frame(minWidth:minHeight:)` together stop the sliver. If the title stays "DeskApp", the window is using the target name because no navigation title was found. Add the stack.

</Solution>
