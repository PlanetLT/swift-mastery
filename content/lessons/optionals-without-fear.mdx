Most crashes in a first Swift app are a value that was missing and a programmer who insisted it was there. Swift makes absence visible. The type `String?` means "a string, or nil".

Nil is not a blank string and not zero. It means there is no value.

## Unwrap on purpose

```swift
func firstWord(in title: String?) -> String {
    guard let title, title.isEmpty == false else {
        return "Untitled"
    }
    return title.split(separator: " ").first.map(String.init) ?? "Untitled"
}

let named = firstWord(in: "Swift Mastery")
let missing = firstWord(in: nil)
```

`guard let` leaves the unwrapped name in scope for the rest of the function, and the `else` must exit. `if let` is the right tool when the rest of the function should still run.

`??` supplies a default. Use it when a default is honest. "Untitled" is honest for a missing title. A default password would not be.

## The mark you should not reach for

```swift
let note: String? = nil
// let crash = note!  // traps if note is nil
let safe = note ?? ""
```

The `!` after a value force-unwraps. If the value is nil, the process stops. Apple's frameworks sometimes return optionals because the thing might not exist yet: a selected row, a URL from a string, a photo the person refused.

<Callout title="Where people stall">

They sprinkle `!` through a sample copied from a video so the next line will compile. The video's author knew the value was present in that one demo. Your app will meet the empty case. Unwrap, or pass the optional along.

</Callout>

## Exercise

Write `port(from input: String) -> Int?` that returns a number only when the whole string is an integer between 1 and 65535. Call it with `"80"`, `"nope"`, and `""`.

<Solution>

```swift
func port(from input: String) -> Int? {
    guard let value = Int(input), (1...65535).contains(value) else {
        return nil
    }
    return value
}
```

`Int(input)` is already optional. The range check belongs in the same `guard`, so callers never see an out-of-range port.

</Solution>
